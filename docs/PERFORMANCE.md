# تحسين الأداء — لوحة التحكم والاستيراد (2026-11-16)

## المشكلة السابقة

- `GetDashboard` استدعى `GetSchools` و`GetLatestSubmissions`، وكان الأخير يستعلم مرتين لكل استمارة للحصول على الرأس والصفوف؛ لذلك زاد عدد الاستعلامات خطيا مع عدد المدارس.
- `ImportSchools` أنشأ `SqliteCommand` جديدا لكل صف في الاستيراد.

## التعديل

1. حساب إحصاءات لوحة التحكم باستعلام SQL تجميعي واحد باستخدام أحدث مراجعة لكل مدرسة وفي الدورة الحالية، مع إدراج الطلاب والمعلمين والفصول **للاستمارات المعتمدة فقط**.
2. استعلام واحد لقراءة أحدث استمارات المدارس وصفوفها وتكوين النتائج في الذاكرة (دون استعلام لكل مدرسة)، مع المحافظة على نطاق المستخدم.
3. إعادة استخدام أمر إدراج واحد مجهز مسبقا `Prepare()` لكل المدارس ضمن معاملة SQLite ذرية، دون تغيير التحقق المسبق.
4. فهرس `ix_submissions_round_school_revision` لتسريع اختيار أحدث مراجعة لكل مدرسة عند تحديد الدورة.

## الفحوص

- اختبار النتائج عند وجود مراجعة مرتجعة وأخرى معتمدة ومسودات واستمارات قيد المراجعة.
- اختبار نطاق مستخدم المدرسة مقارنة بمسؤول المديرية.
- اختبار ذرية استيراد ملف يضم رمز مدرسة موجودا مسبقا.
- اختبار إنشاء الفهرس وإعادة تنفيذ التهيئة.

## خطة القياس عند توفر Windows و.NET SDK

- بيئة قياس قابلة للإعادة: 100 و500 و3000 مدرسة؛ 9 أو 12 صفا لكل مدرسة، مع نسب حالات مختلفة.
- قياس الزمن المتوسط وp95 خلال 20 تكرارا بعد الإحماء، وقيمة ذاكرة العمل وحجم الملف.
- مقارنة `GetDashboard` و`GetLatestSubmissions` و`ImportSchools` بنسخة الأساس عند SHA `7981d4e` مع نفس البيانات.
- لا يجوز ادعاء تحسن رقمي حتى تسجيل قياسات قابلة لإعادة الإنتاج على الجهاز نفسه.

## الدروس المستفادة من الأنظمة المشابهة

- OpenEMIS Census: الفصل بين إدخال استمارات المدارس وتقارير المديرية، وتوفير استيراد وحصر متعدد القنوات.
- Ed-Fi Data Standard: ثبات المعرفات والتعاريف وقابلية الربط؛ لا نحتاج نسخ نموذج البيانات الفردي كاملا من البداية.
- UNESCO UIS EMIS: تحقق جودة البيانات قبل النشر والاعتماد، مع الاحتفاظ بتعريفات المؤشرات.
